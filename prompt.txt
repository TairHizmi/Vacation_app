### Core Features & Specs

#### 1. Database Entities
- Users: ID (PK), First Name, Last Name, Email (unique), Password, Role (User / Admin).
- Vacations: ID (PK), Destination, Description, Start Date, End Date, Price, Cover Image Filename.
- Likes: Many-to-Many junction table linking Users and Vacations.

#### 2. Authentication & Authorization
- Registration Page: All fields required. Email validation required. Minimum password length: 4 characters. Check if email is already taken. Redirect to Vacations page upon completion.
- Login Page: All fields required. Minimum password length: 4 characters. Clear error messages for invalid credentials. Redirect to Vacations page upon completion.
- Protected Routes: Only logged-in users can access core pages. Unauthorized access redirects to Login.

#### 3. User Features (Role: User)
- Vacations Dashboard: Display vacations as responsive Cards (NOT tables). Each card shows all vacation details, total Likes count, and whether the current user liked it.
- Sorting: Automatically sort vacations by Start Date in ascending order.
- Pagination: Strictly 9 vacation cards per page.
- Actions: Toggle Like/Unlike on cards.
- Filters: 4 required filter buttons:
  1. Show only vacations liked by the user.
  2. Show currently active vacations (started and hasn't ended yet).
  3. Show future vacations (haven't started yet).
  4. Reset filters (show all vacations).

#### 4. AI & Advanced Features (Accessible to Registered Users)
- AI Recommendation Page: A text input for a destination. Clicking "Get Recommendation" fetches and displays a structured travel itinerary/recommendation on the page.
- MCP Server Communication Page: An interface with a textarea to ask questions about the database data (e.g., "How many active vacations are there right now?", "What is the average price?", "What are the future vacations in Europe?"). This must communicate with an MCP server built on the backend.

#### 5. Admin Features (Role: Admin)
- Admin Dashboard: Same grid layout but without Like options. Instead, each card has "Edit" and "Delete" buttons.
- Add Vacation Page: All fields required. Prevent negative prices or prices > 10,000. Prevent end dates earlier than start dates. Prevent past dates.
- Edit Vacation Page: Pre-filled fields. All fields required except the cover image (display current image, allow changing it, but don't force a re-upload). Allows past dates (since historical data can be edited).
- Delete Vacation: Prompt a confirmation modal/dialogue before deleting.
- Vacations Report Page: Display a chart showing vacation destinations on the X-axis and total Likes on the Y-axis. (Use any standard chart library like chart.js or recharts).
- Download CSV: An exclusive Admin button to generate and download a `Vacation Likes.csv` file structured as: `Destination, Likes`.

#### 6. Public Page
- About Page: Accessible to unregistered users. Displays information about the system and the developer's details.

#### 7. Navigation & Header
- A dynamic responsive navbar. Unregistered users only see Login/Register. Registered users see their full name, dynamic links based on their role, and a Logout button.
